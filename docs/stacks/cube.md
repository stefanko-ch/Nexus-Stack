## Cube

![Cube](https://img.shields.io/badge/Cube-FF6492?logoColor=white)

**Semantic layer — one definition of a metric, served to every tool**

Superset, Metabase and Evidence each carry their own idea of what "revenue" means. Three definitions drift three ways, and the first sign is usually two dashboards disagreeing in a meeting. Cube holds the definition once and serves it over SQL, REST and GraphQL, so the tools stop owning the arithmetic.

### The two containers

| Container | Role |
|---|---|
| `cube` | The APIs and the Playground UI |
| `cube-store` | Cube's own storage layer: cache, query queue, and materialised pre-aggregations |

`cube-store` is not optional, and that is upstream's position rather than a guess: *"While Cube can operate with in-memory cache and queue storage, there're multiple parts of Cube which require Cube Store in production mode."*

### Usage

1. Enable **Cube** in the Control Plane → Spin Up.
2. Open `https://cube.YOUR_DOMAIN` → Cloudflare Access email OTP → the Playground.
3. The connection to the shared PostgreSQL is already configured. Open **Data model → Generate**, pick the tables you want, and Cube writes a first set of cubes for you.
4. Query them in the Playground, then point a BI tool at the SQL API on the same host.

There is no data model to begin with, and that is the intended starting point — Cube describes tables that already exist rather than creating any of its own. On a fresh stack the warehouse is empty, so create a table first (from a notebook, dbt in code-server, or any of the ingestion stacks) and then generate the model.

### What survives a teardown, and what does not

**The data model does not.** It lives in the `cube-conf` named volume, which is the same trade-off `meltano` makes for a user's project: a named volume survives a container being recreated, not the server being destroyed.

So treat the Playground as a place to draft a model, and keep anything worth keeping in the workspace repository. `cube-store-data` is deliberately not persisted either — cache, queue state and pre-aggregations are all derived from the warehouse and rebuild themselves.

### Authentication, and what "dev mode" costs

The Playground — the reason this stack has a UI at all — exists only in Cube's development mode, and the stack therefore runs with `CUBEJS_DEV_MODE=true`. Upstream is blunt about the price: *"Development mode is an authentication bypass"*, switching off JWT verification on the REST and GraphQL APIs.

That is the same bargain every other stack here makes — no application login, Cloudflare Access at the edge — with one consequence worth stating plainly:

> **Any container on `app-network` can query Cube's API without a token.** Access protects the browser route and never sees in-cluster traffic. On a stack where you trust everything you deployed, that is the existing security model. On a shared one it is a reason to think twice.

`CUBE_API_SECRET` is generated by OpenTofu and published to Infisical under `/cube`. It signs the JWTs a BI tool presents when it connects, and it is not a login — Cube has no user management.

### Why `cube-store` is amd64-only, and what that means

Every other image in this catalogue is multi-arch. `cubejs/cubestore` publishes **amd64 only** for its release tags (there is a separate `-arm64v8` build tag and `-non-avx` variants for CPUs without AVX).

Nexus-Stack has run on x86 `cx43` servers since 2026-05, so this satisfies the requirement in `CLAUDE.md` — the image must support `linux/amd64`. Two practical consequences:

- a contributor on Apple Silicon cannot run `cube-store` locally without emulation;
- Cube Store needs AVX. Hetzner's Intel instances have it; on a CPU without it the container fails at startup rather than degrading quietly, and the `-non-avx` tags exist for exactly that case.

### Configuration

| Variable | Source | Purpose |
|---|---|---|
| `POSTGRES_PASSWORD` | the shared `postgres` stack's secret | Cube's connection to the warehouse (`CUBEJS_DB_PASS`) |
| `CUBE_API_SECRET` | `random_password.cube_api_secret` → Infisical `/cube` | signs and verifies API tokens |

Both are guarded at render time: if either is empty, the deploy stops with a message naming the missing value rather than starting a semantic layer that cannot reach the warehouse it exists to describe.
