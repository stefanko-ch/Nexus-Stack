## HedgeDoc

![HedgeDoc](https://img.shields.io/badge/HedgeDoc-3499D9?logo=hedgedoc&logoColor=white)

**Collaborative real-time Markdown editor (HackMD/StackEdit alternative)**

HedgeDoc is a self-hosted collaborative Markdown editor. Real-time multi-user editing (one URL, many cursors), MathJax / Mermaid / KaTeX / PlantUML rendering, slide-mode (revealjs), version history. The "HackMD you self-host".

| Setting | Value |
|---------|-------|
| Default Port | `3110` (→ container 3000) |
| Suggested Subdomain | `hedgedoc` |
| Public Access | No (Cloudflare Access via email OTP) |
| Website | [hedgedoc.org](https://hedgedoc.org) |
| Source | [GitHub](https://github.com/hedgedoc/hedgedoc) |
| Docker image | [`quay.io/hedgedoc/hedgedoc`](https://quay.io/repository/hedgedoc/hedgedoc) |
| Backing DB | Dedicated Postgres 16 (`hedgedoc-db` container, separate from any shared Postgres) |

### Usage

1. Enable **HedgeDoc** in the Control Plane → Spin Up
2. Open `https://hedgedoc.YOUR_DOMAIN` → CF Access email OTP → HedgeDoc login form
3. Sign in with the admin credentials:
   - **Username**: your `ADMIN_EMAIL` (the same email used as the Infisical / Cloudflare Access identity)
   - **Password**: `infisical secrets get HEDGEDOC_PASSWORD --path=/hedgedoc --plain`
4. Create notes from the **History** page — by default each new note is private to the admin; flip to `editable` / `freely` via the per-note ⚙ permission selector to share

### Auth model (#618)

Two-layer auth, both enforced:

1. **Cloudflare Access** at the edge (email OTP) gates who reaches the HedgeDoc login page at all.
2. **HedgeDoc's own login** with a single seeded admin account is the in-app identity. Self-signup is disabled (`CMD_ALLOW_EMAIL_REGISTER=false`) so the user-pool stays at exactly one. Anonymous editing is off (`CMD_ALLOW_ANONYMOUS=false`) so every note has a clear owner.

The admin account is seeded by the deploy pipeline (`services.py::render_hedgedoc_hook`) via `node /hedgedoc/bin/manage_users --add EMAIL --pass PASS` against the running container. Idempotent: re-runs detect the existing user and fall back to `--reset` so a rotated `random_password.hedgedoc_admin` (or an R2-snapshot restore from a stack with a different password) re-converges the in-DB hash with the Infisical-stored secret.

If you need multi-user accounts (Workshop / pair-collaboration), flip `CMD_ALLOW_EMAIL_REGISTER=true` in `stacks/hedgedoc/docker-compose.yml` and re-deploy. New users will see a "Sign Up" link on the login page; they hit the same CF Access OTP at the edge first, then can register an in-app account.

### Secrets

Generated by OpenTofu (`random_password.hedgedoc_admin`, `random_password.hedgedoc_session_secret`, `random_password.hedgedoc_db_password`) and pushed to Infisical under folder `/hedgedoc`:

- `HEDGEDOC_USERNAME` — admin email (same as your `ADMIN_EMAIL`)
- `HEDGEDOC_PASSWORD` — admin login password (24 chars)
- `HEDGEDOC_SESSION_SECRET` — signs the session cookie (32 chars)
- `HEDGEDOC_DB_PASSWORD` — Postgres password for the dedicated `hedgedoc-db` container

All four must be non-empty or the deploy aborts with a clear `ServiceEnvError` (no silent insecure-sessions / lockout fallback).

### Persistence (#618)

- `hedgedoc-db` Postgres → captured via `pg_dump` (`PostgresDumpTarget(container="hedgedoc-db", database="hedgedoc", user="nexus-hedgedoc")`)
- `/mnt/nexus-data/hedgedoc/uploads` bind-mount → captured via `rsync` (`RsyncTarget(name="hedgedoc-uploads", s3_subpath="hedgedoc/uploads")`)

Both targets live in `src/nexus_deploy/s3_restore.py::standard_targets` and run on every `teardown` (push to R2) + `spin-up` (restore from R2). Notes and image attachments survive teardown cycles without operator intervention.

The uploads bind-mount path is mkdir+chowned to `10000:10000` (the in-container `hedgedoc` user) by `compose_runner.render_remote_script`'s `hedgedoc_uploads_prep` block before the compose-up runs, so first-upload doesn't fail with EACCES.

### Troubleshooting

- **"This site can't be reached"**: CF Access cookie expired — refresh, do OTP again
- **Real-time sync stuck (cursors don't move for other users)**: HedgeDoc uses a WebSocket connection on `/socket.io/` for the live-cursor sync. Cloudflare Tunnel allows WebSockets by default for the ingress rules nexus-stack provisions in `tofu/stack/main.tf`. If sync breaks, check `docker logs hedgedoc | grep -i socket` on the server — it usually means the client browser failed the WS upgrade (network filter, ad-blocker). Plain document edits still save via HTTPS POST and are visible on page reload
- **Image uploads fail**: check `docker logs hedgedoc | grep upload` — usually the `hedgedoc-uploads` volume is full (no resize logic; bump the host disk and restart the container)
