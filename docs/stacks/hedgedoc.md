## HedgeDoc

![HedgeDoc](https://img.shields.io/badge/HedgeDoc-3499D9?logo=hedgedoc&logoColor=white)

**Collaborative real-time Markdown editor (HackMD/StackEdit alternative)**

HedgeDoc is a self-hosted collaborative Markdown editor. Real-time multi-user editing (one URL, many cursors), MathJax / Mermaid / KaTeX / PlantUML rendering, slide-mode (revealjs), version history. The "HackMD you self-host".

| Setting | Value |
|---------|-------|
| Default Port | `3110` (→ container 3000) |
| Suggested Subdomain | `hedgedoc` |
| Public Access | No (Cloudflare Access via email OTP) |
| Website | [hedgedoc.org](https://hedgedoc.org) |
| Source | [GitHub](https://github.com/hedgedoc/hedgedoc) |
| Docker image | [`quay.io/hedgedoc/hedgedoc`](https://quay.io/repository/hedgedoc/hedgedoc) |
| Backing DB | Dedicated Postgres 16 (`hedgedoc-db` container, separate from any shared Postgres) |

### Usage

1. Enable **HedgeDoc** in the Control Plane → Spin Up
2. Open `https://hedgedoc.YOUR_DOMAIN` → CF Access email OTP → HedgeDoc home
3. Click **New guest note** → share the URL with your audience — they hit the same OTP gate, then can edit collaboratively in real-time

### Classroom workflow

- **Joint workshop notes**: instructor creates a note for the session, shares the URL on slide one, students take collaborative notes during the talk
- **Pair-coding setup**: students write Markdown pseudo-code or design docs together before opening code-server
- **Slide-mode demos**: any note becomes a revealjs slide deck by adding `tags: presentation` to the front-matter — useful for student final-project presentations

### Auth model

The shipped compose deliberately **disables HedgeDoc's own email signup** (`CMD_ALLOW_EMAIL_REGISTER=false`). Access control is delegated to **Cloudflare Access at the edge** (email OTP) so we don't run a second login layer. Inside the gate, **anonymous notes are enabled** (`CMD_ALLOW_ANONYMOUS=true`) — anyone with the URL who's passed CF Access can read/edit. This matches the classroom use case where the instructor wants to drop a shareable link in chat without managing per-student accounts.

If you want per-user history (notes attributed to a user) instead of anonymous edits, flip `CMD_ALLOW_EMAIL_REGISTER=true` and `CMD_ALLOW_ANONYMOUS=false` in `stacks/hedgedoc/docker-compose.yml` and re-deploy.

### Secrets

Generated by OpenTofu (`random_password.hedgedoc_session_secret`, `random_password.hedgedoc_db_password`) and pushed to Infisical under folder `/hedgedoc`:

- `HEDGEDOC_SESSION_SECRET` — signs the session cookie (32 chars)
- `HEDGEDOC_DB_PASSWORD` — Postgres password for the dedicated `hedgedoc-db` container

Both must be non-empty or the deploy aborts with a clear `ServiceEnvError` (no silent insecure-sessions fallback).

### Persistence

- `hedgedoc-uploads` volume: image / file attachments uploaded into notes
- `hedgedoc-db-data` volume: Postgres data (notes, history, user metadata)

Both included in the S3-persistence snapshot loop (`NEXUS_S3_PERSISTENCE=true`).

### Troubleshooting

- **"This site can't be reached"**: CF Access cookie expired — refresh, do OTP again
- **Real-time sync stuck (cursors don't move for other users)**: HedgeDoc uses a WebSocket connection on `/socket.io/` for the live-cursor sync. Cloudflare Tunnel allows WebSockets by default for the ingress rules nexus-stack provisions in `tofu/stack/main.tf`. If sync breaks, check `docker logs hedgedoc | grep -i socket` on the server — it usually means the client browser failed the WS upgrade (network filter, ad-blocker). Plain document edits still save via HTTPS POST and are visible on page reload
- **Image uploads fail**: check `docker logs hedgedoc | grep upload` — usually the `hedgedoc-uploads` volume is full (no resize logic; bump the host disk and restart the container)
